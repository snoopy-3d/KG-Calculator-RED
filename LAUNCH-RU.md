# Подробный запуск на Windows

Инструкция от 31 октября 2026 года. Никакие изменения в GitHub за вас не выполнены. Запуск рассчитан на бесплатный Cloudflare Workers с SQLite Durable Objects. Не подключайте платный план ради прохождения инструкции; при предложении оплаты сначала проверьте выбранный продукт и действующие условия.

## 1. Сначала замените раскрытый токен

1. Откройте Telegram и официальный **@BotFather**. Проверьте имя: именно `BotFather`.
2. Отправьте `/revoke` и выберите нужного бота. Старый токен станет недействительным.
3. Если новый токен не выдан автоматически, отправьте `/token` и выберите того же бота.
4. Сохраните новый токен в менеджере паролей. Не присылайте его в чат, не вставляйте в файлы проекта, Issues, GitHub Secrets или адресную строку браузера.
5. В BotFather через `/setname` задайте название `KG Calculator RED`. Если бот уже используется старым сервером, остановите его: одновременно старый polling и новый webhook работать не должны.

## 2. Проверьте репозиторий

Откройте https://github.com/snoopy-3d/KG-Calculator-RED под своим аккаунтом. При подготовке оба запроса GitHub — к описанию репозитория и корневым файлам — вернули 404. Это не доказывает, что репозитория нет: возможен закрытый доступ.

Если репозиторий открывается, посмотрите вкладку **Code**. Если там есть файлы, сохраните копию через **Code → Download ZIP**. Не заменяйте существующий проект вслепую. Предоставьте архив существующего кода для сравнения, предварительно удалив секреты. Подготовленный пакет пока не был объединён с этим кодом.

Если GitHub действительно не находит репозиторий, проверьте имя владельца и название. При необходимости создайте его: **+ → New repository**, Owner `snoopy-3d`, Repository name `KG-Calculator-RED`, выберите видимость, затем **Create repository**. Публичный код не должен содержать секретов. Если экран загрузки недоступен в пустом репозитории, создайте первый README через предложенную GitHub ссылку создания файла.

## 3. Подготовьте инструменты и папку

1. Установите Node.js **24 LTS** с https://nodejs.org/en/download, оставив установку npm включённой.
2. Закройте и снова откройте PowerShell.
3. Проверьте `node --version` и `npm.cmd --version`. Должны появиться номера версий. Использование `npm.cmd` помогает избежать блокировки PowerShell для `npm.ps1`.
4. Распакуйте полученный архив, например в `C:\KG-Calculator-RED`. Внутри должны находиться `package.json`, `wrangler.toml`, `src` и `docs`, а не ещё одна вложенная папка проекта.
5. Откройте эту папку в Проводнике. Нажмите адресную строку, напишите `powershell` и нажмите Enter. Команды ниже выполняйте в этом окне по одной.

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run check:deploy
```

Продолжайте, только если проверки завершились успешно. Последняя команда собирает проект, но ещё не размещает его. Не загружайте `node_modules` и `.wrangler` в GitHub.

## 4. Загрузите файлы в GitHub самостоятельно

Для пустого репозитория можно использовать браузер:

1. Откройте **Code → Add file → Upload files**.
2. Перетащите содержимое папки проекта: `src`, `scripts`, `test`, `docs`, `package.json`, `package-lock.json`, `wrangler.toml`, `README.md`, `.gitignore`, `.github`.
3. В Windows включите **Вид → Показать → Скрытые элементы**, чтобы увидеть `.github` и `.gitignore`. Проверьте, что `.github/workflows/check.yml` попал именно по этому пути.
4. Не загружайте ZIP вместо распакованных файлов: Cloudflare нужен код, а не архив. Не загружайте `node_modules`, `.wrangler`, `.dev.vars`, `.env` и журналы.
5. В поле описания напишите `Prepare KG Calculator RED v1`.
6. Выберите создание новой ветки `prepare-bot-v1`, если GitHub предлагает этот вариант; нажмите **Propose changes**, затем **Create pull request**. Проверьте список файлов и зелёные проверки. Нажмите **Merge pull request → Confirm merge**. Все эти действия выполняете вы.
7. Если в пустом репозитории доступна только прямая первая публикация, загрузите файлы в основную ветку и затем проверьте **Actions → Проверки**. Это допустимо для первого пустого проекта.
8. В корне репозитория должен быть `package.json`, а не папка `KG-Calculator-RED/package.json`. Во вкладке **Actions** дождитесь успешного выполнения задания «Проверки». Оно ничего не развёртывает и не использует секреты.

Если в репозитории уже был код, этот шаг выполняйте только после его сравнения с пакетом. История GitHub сохраняет старые секреты даже после удаления файла; раскрытые ключи всегда перевыпускаются.

## 5. Войдите в Cloudflare и создайте Worker

1. Откройте https://dash.cloudflare.com и создайте аккаунт либо войдите. Подтвердите почту, если это требуется.
2. В том же PowerShell в папке проекта выполните:

```powershell
npx.cmd wrangler login
```

3. Откроется браузер: разрешите официальному Wrangler доступ к своему Cloudflare. Вернитесь в окно PowerShell после успешной авторизации. Не присылайте коды авторизации в чат.
4. Выполните:

```powershell
npm.cmd run deploy
```

5. При первом запуске Cloudflare может предложить выбрать/создать поддомен `workers.dev`. Следуйте подсказке и сохраните итоговый адрес вида `https://kg-calculator-red.ВАШ-ПОДДОМЕН.workers.dev`.
6. Команда создаёт Worker и SQLite Durable Objects через конфигурацию `wrangler.toml`. Отдельная база D1 и ручное копирование её ID не нужны.
7. До добавления секретов `/telegram` отвечает 503 — это ожидаемо. Откройте итоговый адрес с `/health`: должно появиться `ok`.

Вариант запуска через локальный Wrangler выбран, чтобы не хранить токен Cloudflare в GitHub и не зависеть от меняющихся экранов настройки сборки. Связывать Cloudflare с GitHub для этой версии не требуется. Код при этом остаётся в вашем репозитории; публикацию выполняет команда из проверенной локальной копии.

## 6. Добавьте секреты Cloudflare

Выполните:

```powershell
npx.cmd wrangler secret put TELEGRAM_BOT_TOKEN
```

На скрытый запрос вставьте **новый** токен BotFather. Нажмите Enter. Не пишите токен в самой команде: так он не попадёт в историю команд.

Создайте случайный webhook-секрет из 32 случайных байт:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Сохраните полученные 64 символа в менеджере паролей. Это отдельный секрет, не токен Telegram. Затем:

```powershell
npx.cmd wrangler secret put WEBHOOK_SECRET
```

Вставьте сгенерированное значение на скрытый запрос. Не публикуйте его. Для проверки наличия имён секретов без вывода значений:

```powershell
npx.cmd wrangler secret list
```

Альтернатива — кабинет Cloudflare: **Workers & Pages → kg-calculator-red → Settings → Variables and Secrets → Add**, тип **Secret**, точное имя из инструкции. Обычный текстовый тип не используйте. Названия экранов могут меняться. Не дублируйте секреты в `[vars]` файла.

## 7. Подключите необязательный ИИ

Без этого шага бот работает с быстрыми ответами. Для резервирования нужны два отдельных аккаунта и два ключа.

1. Откройте https://console.groq.com, создайте аккаунт, проверьте бесплатный план и доступность `llama-3.3-70b-versatile` в Playground. В **API Keys** создайте ключ для этого бота. Не включайте платный тариф. Доступность по стране/аккаунту проверяется на стороне сервиса.
2. Сохраните ключ командой `npx.cmd wrangler secret put GROQ_API_KEY` через скрытый ввод.
3. Откройте https://openrouter.ai, создайте аккаунт. На странице https://openrouter.ai/settings/keys создайте отдельный ключ. Пополнять баланс для инструкции не требуется. Убедитесь, что бесплатный маршрут доступен вашему аккаунту.
4. Сохраните ключ: `npx.cmd wrangler secret put OPENROUTER_API_KEY`.
5. Откройте `wrangler.toml` в текстовом редакторе, замените `AI_ENABLED = "false"` на `AI_ENABLED = "true"` и сохраните. Внесите такое же изменение в GitHub самостоятельно: откройте файл → значок карандаша → измените строку → **Commit changes**, желательно через ветку и pull request.
6. Снова запустите проверки и публикацию:

```powershell
npm.cmd test
npm.cmd run check:deploy
npm.cmd run deploy
```

Groq используется первым; при его ошибке бот попробует OpenRouter с `openrouter/free`. Если оба недоступны, остаются быстрые ответы. Квоты и перечень моделей меняются; гарантированной доступности нет. Проект не обращается к ChatGPT и не использует вашу подписку. Ключи сервисов расходуют их собственные квоты. Если у Groq уже включена оплата, код не может запретить её на уровне аккаунта: используйте аккаунт на бесплатном плане.

Для отключения ИИ верните `AI_ENABLED = "false"` и повторите публикацию. Другие разделы продолжат работать.

## 8. Установите webhook без публикации токена

После добавления секретов и публикации выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\telegram-setup.ps1
```

Это одноразовый запуск подготовленного скрипта; глобальная политика Windows не меняется. Он по очереди попросит:

1. Новый токен BotFather — ввод скрыт.
2. **Тот же** `WEBHOOK_SECRET`, который вы сохранили в Cloudflare — ввод скрыт.
3. Адрес Worker `https://…workers.dev` без `/telegram` — обычный ввод.

Скрипт проверит токен, настроит команды и описание, установит webhook `/telegram` с секретным заголовком, включит сообщения и кнопки, проверит итоговый адрес. Очередь сообщений не удаляется. Значения секретов очищаются из переменных процесса при завершении. Скрипт не выводит полное тело ответа Telegram, поскольку оно может содержать чувствительные сведения.

Не открывайте URL вида `api.telegram.org/botТОКЕН/...` в браузере и не отправляйте такие ссылки в чат. При смене токена повторите шаг сохранения `TELEGRAM_BOT_TOKEN` и этот шаг настройки.

## 9. Проверьте реального бота

1. Откройте своего бота в Telegram. Нажмите **Start** или отправьте `/start`.
2. Убедитесь, что видны только «Духи», «Мой профиль», «Помощь».
3. В профиле нажмите «Изменить мощь», введите полное целое число из игры. Снова откройте профиль: оно должно сохраниться.
4. В «Духи» выберите уровень. До загрузки данных появится «Проверенный порог пока не добавлен». Это ожидаемо.
5. Откройте «Кого крепить»: пока подтверждённых правил нет, рекомендации не показываются.
6. В «Помощь» проверьте быстрые ответы. Если включили ИИ, нажмите помощника, согласитесь на передачу вопроса и спросите «Как поменять мощь?». Ответ должен объяснить профиль.
7. Проверьте второй аккаунт Telegram: мощь первого игрока не должна появиться у второго.
8. В профиле нажмите «Удалить профиль» и подтвердите. Повторное открытие должно показать «не указана».
9. Сохраните мощь снова, выполните повторный `npm.cmd run deploy`, затем проверьте, что она сохранилась. Не переименовывайте binding, класс и миграцию без отдельного переноса данных.

Если бот молчит: проверьте `/health`, наличие секретов, совпадение webhook-секрета, результат скрипта настройки и отсутствие старого запущенного бота. После превышения 20 действий за минуту подождите минуту. В Cloudflare смотрите **Worker → Observability/Logs**; не включайте запись тел и заголовков. Ошибка `update_processing_failed` не содержит секретов. Из-за защиты от повторной обработки отдельный ответ при сбое может потеряться: повторите действие новым сообщением.

## 10. Как добавить реальные игровые данные

Подготовьте таблицу: уровень, полное значение порога, единицы, свидетельство проверки и дата. Уточните, к какой версии игры относятся значения. Не используйте числа из демонстрационных макетов.

В `src/data.mjs` добавляйте объекты только после проверки. Схема: `{ level, power, verified: true, evidence, verifiedAt }`; все значения здесь названия полей, не готовая игровая запись. Одна запись на уровень. Не сохраняйте приватные скриншоты, личные сведения и закрытые ссылки в публичном коде.

После добавления — проверки, ручной просмотр дефицита/равенства/запаса на проверенном уровне, загрузка изменения в GitHub вами и повторная публикация Worker. Смена кода не требует повторной настройки webhook, если адрес, токен и секрет не изменились. Правила «Кого крепить» и калькуляторы требуют отдельных подтверждённых требований, а не заполнения случайными числами.

## 11. Обновления, остановка и восстановление

Для каждого обновления используйте одну и ту же папку проверенного проекта: внесите изменения, выполните `npm.cmd test` и `npm.cmd run check:deploy`, загрузите их в GitHub самостоятельно, затем `npm.cmd run deploy`. Деплой из локальной папки не читает автоматически последнюю версию GitHub. Если редактировали код только на GitHub, сначала скачайте актуальную копию и выполните проверки в ней.

При неудачном релизе в Cloudflare **Deployments** выберите предыдущую успешную версию и **Rollback**, если доступно, либо повторно разместите сохранённую рабочую копию командой deploy. Откат кода не восстанавливает удалённые профили и не отменяет изменения данных. Эта версия не содержит автоматического резервного копирования; перед будущими миграциями нужен отдельный план сохранения.

При компрометации токена немедленно `/revoke` в BotFather, затем сохранение нового токена в Cloudflare и повторная настройка webhook. Для остановки выключите Worker через кабинет Cloudflare; это останавливает обработку, но само по себе не удаляет профили. Удаление Worker/хранилища может быть необратимым — не используйте его как обычный способ обновления.
