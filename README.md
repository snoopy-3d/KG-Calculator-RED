# Kingdom Guard Calculator RED

Стартовая версия Telegram-бота на Python 3.12 и aiogram 3. Личные профили сохраняются в SQLite. Работает только в личном чате.

## Возможности

- `/start`: создать профиль по Telegram ID; повторный запуск сохраняет сервер и сезон.
- `/profile`: имя, сервер и сезон.
- `/server 123`, `/season S1`: сохранить собственные метки (1–40 символов). Они не сверяются с игровым справочником.
- `/calc`: меню «Прокачка», «События», «Ресурсы».
- `/help`, `/cancel`: помощь и главное меню.
- `/delete_profile`: немедленно удалить свой профиль. Следующий `/start` или `/profile` создаст его заново.

Игровые формулы отсутствуют намеренно. Все разделы калькуляторов отвечают, что расчёты недоступны до проверки таблиц и формул. Учёт ресурсов и связь с игрой пока не реализованы. Для подключения расчётов нужны источник, версия игры/сезон, условия применимости и проверенные примеры с ожидаемыми результатами.

## Запуск с телефона через Render

1. Распакуйте архив на телефоне. В GitHub откройте репозиторий → Add file → Upload files и выберите все распакованные файлы. Загружайте их прямо в корень, без папки. Если README.md уже есть, замените его новой версией через редактор GitHub. Сохраните изменения кнопкой Commit changes.
2. Откройте https://dashboard.render.com/ с телефона, подключите GitHub и разрешите доступ к репозиторию.
3. Выберите **New → Blueprint**, затем этот репозиторий. Render прочитает `render.yaml`.
4. Проверьте стоимость перед созданием: конфигурация создаёт платный Background Worker и постоянный диск 1 GB. Это не бесплатный запуск. Подтвердите создание только если тариф подходит.
5. В защищённое поле `BOT_TOKEN` вставьте актуальный токен из BotFather. Не отправляйте его в чат, README, GitHub или скриншоты. Если токен когда-либо был раскрыт, отзовите его в BotFather.
6. Дождитесь успешного развёртывания. Откройте своего бота в Telegram, отправьте `/start`, задайте сервер и сезон, проверьте `/profile`.
7. Перезапустите worker из панели Render и убедитесь, что профиль сохранился.

`DATABASE_PATH=/var/data/profiles.sqlite3` указывает на постоянный диск. Храните ровно один экземпляр worker на токен: long polling не рассчитан на несколько одновременно работающих копий. Веб-сервис и публичный HTTP-порт не нужны. При старте снимается webhook без удаления накопленных обновлений. Секрет не включается в сборку.

Документация: [Render Blueprint](https://render.com/docs/blueprint-spec), [постоянные диски](https://render.com/docs/disks), [aiogram polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html).

## Разработка и тесты

```sh
python -m venv .venv
# Activate the environment for your shell, then:
pip install -r requirements.txt
python -m unittest -v test_bot
# Set BOT_TOKEN in the process environment, then:
python main.py
```

`.env.example` — только образец переменных. Программа не загружает `.env` автоматически. Обязательная переменная — `BOT_TOKEN`; `DATABASE_PATH` по умолчанию — `data/profiles.sqlite3`.

Render перед запуском автоматически выполняет тесты без реального токена и без запросов к Telegram. Тесты проверяют изоляцию пользователей, сохранение данных после повторного открытия БД, валидацию, удаление и обработчики через имитацию Telegram. Живое подключение проверяется после размещения с вашим секретом.

## Данные и эксплуатация

Хранятся Telegram ID, текущее отображаемое имя, сервер и сезон. Доступ к данным в боте ограничен ID отправителя. Владелец хостинга имеет доступ к базе; ограничьте доступ к панели и делайте защищённые резервные копии диска. Удаление профиля не удаляет старые резервные копии: срок хранения определяет владелец. Смена схемы БД в будущих версиях потребует миграций.

Ошибки запуска выводят общее сообщение без текста исключений, чтобы не раскрыть токен. Проверьте секрет, доступ к Telegram и путь диска при сбое. Работоспособность реального бота и размещение не подтверждаются одними тестами.

## Проверка подготовленного комплекта

Все 7 автоматических тестов прошли на Python 3.12. Реальный Telegram и развёртывание на Render ещё не проверены. Доступ к исходному репозиторию при подготовке возвращал 404, поэтому его содержимое не проверено и изменений в GitHub не внесено.
