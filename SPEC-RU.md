# Техническое задание KG Calculator RED — 1.0

Дата: 31 октября 2026 года. Основание: требования пользователя и доступная история чата «Размещение бота на GitHub».

## 1. Назначение и границы

Бот помогает сохранить мощь игрока и сравнить её с проверенным порогом выбранного уровня духа. Он не оценивает вероятность победы, не обещает прохождение и не подставляет отсутствующие игровые данные. Порог — справочное подтверждённое значение, а не гарантия результата.

Первая версия работает только в личном чате. Группы, каналы, изображения, голосовые сообщения, платежи, реклама, админ-панель, импорт из игры и автоматическое чтение скриншотов не входят в объём. Название игры и эмодзи используются в тексте; Telegram не позволяет произвольно перекрасить кнопки или задать собственный шрифт. Оформление строится на едином названии, коротких заголовках и тематических значках.

## 2. Интерфейс и навигация

Главная клавиатура содержит ровно три кнопки:

```text
🔴 KG Calculator RED
⚔️ Добро пожаловать, командир!
Выберите раздел.

[            👻 Духи            ]
[ 👤 Мой профиль ] [ ❓ Помощь ]
```

«Духи»: «Выбрать уровень», «Кого крепить», «Главное меню». В «Кого крепить» есть возврат к духам. «Мой профиль»: текущая мощь, изменение мощи, удаление с подтверждением, возврат. «Помощь»: о духах, о профиле, об усилении, данные, ИИ-помощник, возврат. Команды `/start` и `/cancel` сбрасывают ожидание ввода и открывают меню.

Открытие главного раздела отменяет предыдущий ввод. Кнопки главного меню остаются доступны. «Калькуляторы» не показываются и не имеют обработчиков; будущие формулы добавляются отдельным изменением после получения проверенных сведений.

Пользовательские ответы короткие, на русском, без названий провайдеров, ссылок на внутренние материалы, технических ошибок, ключей и служебных журналов. Пояснение передачи вопроса внешним сервисам показывается до согласия, поскольку влияет на решение пользователя.

## 3. Духи и игровые данные

Перед выбором уровня должна быть сохранена мощь. Ввод мощи: целое число 0…9 007 199 254 740 991 без пробелов и сокращений. Ввод номера уровня: 1…10000; это техническое ограничение ввода, не утверждение о количестве уровней в игре.

При наличии порога ответ содержит номер уровня, мощь игрока, порог и одну строку: «Не хватает: N» или «Запас: N». Разница = мощь − порог. При равенстве отображается «Запас: 0». Вычисления выполняются кодом, без ИИ. Числа форматируются по-русски.

При отсутствии данных показываются мощь и фраза «Проверенный порог пока не добавлен». Не выводятся нули вместо неизвестных значений, интерполяции, приблизительные оценки и прогнозы. В «Кого крепить» до получения правил отображается честная заглушка. Конкретные герои и рекомендации не выдумываются.

Источник данных: `data.mjs`. Каждая запись содержит уникальный `level`, целочисленный `power`, `verified: true`, внутреннее свидетельство проверки `evidence` и дату `verifiedAt` в формате YYYY-MM-DD. Дубликаты уровня блокируют его использование. Свидетельство хранится только для владельца и не выводится игрокам. Поскольку код GitHub может быть публичным, свидетельства не должны содержать личные данные. Сами источники пользовательских ответов не показываются.

Добавление данных требует проверки владельцем: соответствие уровню и версии игры, единицы измерения, полное значение мощи. Автоматическая проверка структуры не устанавливает истинность игровых чисел. Тестовые числа существуют только в тестах и не загружаются в рабочую таблицу.

## 4. Профили

Ключ профиля — Telegram ID. Хранятся мощь и текущее состояние диалога. Имя, username, контактные данные, история сообщений и история ИИ-вопросов приложением не сохраняются. Изоляция обеспечивается отдельным Durable Object на ID пользователя, подтверждённым личным чатом.

Обновление профиля переживает перезапуск Worker. Удаление требует отдельного подтверждения и удаляет запись `profile`. Технические маркеры обработки и ограничения частоты могут оставаться до суток; это не полное удаление аккаунта из Telegram или резервных копий платформы. После удаления новое действие создаёт новый пустой профиль. Автоматического экспорта и резервного копирования в версии 1.0 нет.

## 5. ИИ и отказоустойчивость

ИИ необязателен: при `AI_ENABLED=false` профиль, духи и быстрые ответы работают самостоятельно. Последовательность при включении: Groq → OpenRouter (`openrouter/free`) → короткое сообщение недоступности. Отсутствующий ключ пропускается. Переключение выполняется при ошибке сети, таймауте, HTTP-ошибке, неверном JSON, пустом или недопустимом результате. Таймаут каждого ИИ-запроса — 5,5 секунды; повторов на том же провайдере нет.

Только после согласия передаётся один вопрос длиной до 600 символов, без добавления ID и профиля. Пользователь сам может включить личные сведения в текст, поэтому до ввода предлагается их не отправлять. Обработка и хранение у провайдеров регулируются их условиями, а не этим проектом.

Модель возвращает только один идентификатор из фиксированного списка. Ответ модели не показывается пользователю: код подставляет утверждённый ответ. Такая реализация помощника ограничена инструкциями по боту. Полноценные ответы о механиках игры потребуют отдельной проверенной базы знаний и расширения ТЗ. Ошибочная классификация может дать неподходящий FAQ, но не произвольный текст модели.

Бесплатность зависит от аккаунтов и действующих условий. Для Groq владелец использует бесплатный план без перехода на платный; код не управляет биллингом аккаунта. OpenRouter вызывается только с маршрутом бесплатных моделей. Нельзя обещать доступность, фиксированные квоты или отсутствие будущих изменений тарифов. Ключ OpenAI и подписка ChatGPT не используются.

## 6. Развёртывание и безопасность

Cloudflare Worker принимает POST `/telegram`, проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`, тип JSON, размер до 16 КБ, корректность update_id, личный чат и совпадение отправителя с ID чата. GET `/health` сообщает только `ok` и не проверяет ключи или Telegram.

Секреты: `TELEGRAM_BOT_TOKEN`, `WEBHOOK_SECRET`, необязательные `GROQ_API_KEY`, `OPENROUTER_API_KEY`. Хранение — Cloudflare Secrets. Они не входят в код, git, архив, инструкции или обычные настройки vars. Раскрытый ранее токен отозвать до запуска. Скрипт настройки получает секреты через скрытый ввод, отправляет Telegram JSON POST, не печатает токены и тело ошибок.

Лимит — 20 событий на игрока за минуту, включая кнопки. Сверх лимита события молча подтверждаются, чтобы не создавать поток ответов. Максимум обычного текста — 1000 символов. Переданный webhook-секрет не заменяет защиту аккаунтов и не предотвращает атаки множеством реальных пользователей. Общие квоты платформ и ИИ остаются внешним ограничением.

Запросы одного пользователя сериализуются. update_id фиксируется до обработки, повторные/более старые события в пределах активного окна не исполняются снова. Это осознанная семантика «не более одной попытки»: если внешняя отправка или процесс оборвались после фиксации, ответ может потеряться; гарантии exactly-once нет. Пользователь может повторить действие новым сообщением. При недоступном хранилище до фиксации возвращается 503 для повтора Telegram. Максимальное число webhook-соединений в настройке — 1 для упорядочивания доставки.

Технические маркеры последних 100 событий, верхний update_id и лимит хранятся до суток после последнего обработанного действия, затем удаляются alarm. Через сутки повтор старого события теоретически возможен; бессрочный журнал намеренно не хранится. При ошибке журнал содержит только общий код `update_processing_failed`, без тела запроса, URL с токеном и личных данных. Не включать журналирование заголовков или тел запросов средствами платформы.

## 7. Приёмка

1. В личном чате `/start` показывает ровно три раздела; калькуляторов нет.
2. Мощь сохраняется и видна после повторного открытия профиля и обновления Worker.
3. Неверный ввод не меняет сохранённую мощь; отмена завершает ввод.
4. Подтверждённый порог даёт корректные дефицит, ноль и запас; неизвестный уровень не получает выдуманного числа.
5. Правила усиления без данных не генерируются.
6. Удаление без подтверждения не срабатывает; после подтверждения мощь отсутствует.
7. Два реальных пользователя не видят профили друг друга.
8. Неверный webhook-секрет даёт 403; слишком большой запрос — 413; группы игнорируются.
9. Дубликат update_id не отправляет второй ответ. Ограничение частоты работает.
10. HTTP-ошибка/таймаут первого ИИ вызывает резервного; сбой всех даёт краткий ответ без технических подробностей.
11. До согласия ИИ не вызывается; произвольный текст модели не попадает в Telegram.
12. Нет секретов в файлах репозитория и логах. Выполнены unit-тесты, сборка и проверка на настоящем аккаунте.

Готовность к публичному запуску: выполнены пункты приёмки в Cloudflare/Telegram, перевыпущен токен, проверены аккаунты провайдеров, загружены первые игровые данные либо владелец явно принимает запуск с пустой базой. Подготовка кода сама по себе не означает, что бот уже размещён.
