# Обновление 1.1: альянсы, игроки и волны духов

Дата подготовки: 31 октября 2026 года. Этот документ заменяет прежние утверждения о пустой базе порогов и отсутствии загрузки игроков. В первой версии этих функций не было; теперь они реализованы.

Обновление размещено в Cloudflare: версия `25ead007-c188-40ea-99c3-0c3cbc562ca8`. Секреты, адрес и webhook сохранены. Изменения ещё нужно самостоятельно загрузить в GitHub; локальная публикация не обновляет репозиторий.

## Что изменилось

- «Духи → Сервер и альянс»: группы серверов, страницы с серверами, список альянсов только выбранного сервера, состав альянса.
- Можно ввести номер сервера сразу, без просмотра группы.
- «Сравнить с уровнем»: сначала уровень события от 1 до 300, затем отдельная кнопка волны от 1 до 20. Уровень события и номер волны не смешиваются.
- Отчёт содержит только участников с текущей мощью ниже мощности выбранной волны. Ники и дефицит выделены жирным, ID не отображаются. Равенство и запас исключаются из списка. Порядок — от самого слабого игрока.
- «Кого крепить» ведёт к сравнению выбранного альянса либо к выбору сервера. Это арифметический дефицит относительно таблицы, без прогнозов победы и без указаний, какое число войск гарантирует прохождение.
- Поиск по игровому ID остаётся способом загрузки. ID используется внутри и не печатается в карточке или отчёте. Сохранение текущей мощи игрока в профиль требует подтверждения. Обновление профиля сначала показывает новую запись, затем требует подтверждения замены.
- Ручной ввод мощи продолжает работать; после него прежняя привязка к загруженному игроку сбрасывается.
- Удаление профиля очищает также игровой ID, импортированную запись и настройки выбора альянса.

## Источники и точность

Публичный API сайта https://kg.dbapp.ru используется только на чтение:

```text
GET /api/clusters
GET /api/clusters/{group}
GET /api/server/{server}/alliances
GET /api/alliance/{id}
GET /api/character/{id}
```

Используется `power`, а не `maxPower`. Максимальная мощь показывается отдельно в карточке. Цифры не округляются до миллионов или миллиардов. Строковые числа обрабатываются через BigInt; если источник уже прислал небезопасное числовое значение, загрузка отклоняется вместо молчаливого округления. Ники и названия при выводе жирного текста экранируются от HTML-вставок.

Кэш публичных ответов — до 5 минут на узле Cloudflare, при доступности Cache API. Метка «Загружено» обозначает время получения данных ботом, а не время изменения записи в самой игре. Источник не гарантирует актуальность относительно текущего состояния игры. Ошибка сайта не затирает сохранённую мощь. Составы не копируются в репозиторий и не записываются целиком в профиль; загружаются по запросу. Приложение не отправляет Telegram ID в игровую базу.

Мощности волн получены из https://api.kgcalc.ru/spiritsInvasion/tableData — это данные калькулятора https://kgcalc.ru/calculators/spiritInvasion. Снимок сохранён в `data.mjs`: 300 уровней × 20 волн, из них 5420 положительных значений, 580 отсутствующих значений не используются. Это проверка соответствия опубликованному калькулятору, а не независимое подтверждение игровых значений. Поле `requiredData.requiredPower` в API относится к очкам открытия уровней и НЕ применяется как мощь волны.

Сверка с расчётным POST /spiritsInvasion выполнена для уровней 19 и 100: результаты wave19Power совпали с таблицей. Калькулятор отдельно предупреждает о возможной погрешности 19-й волны; бот сохраняет это предупреждение в результатах. Никакие пропуски не интерполируются. Если порог отсутствует, отчёт о дефиците не формируется.

Игроки и альянсы обновляются по запросу; таблица волн — фиксированный снимок от 31 октября 2026. Автоматического фонового обновления таблицы волн и проверки всех чисел по игре нет. При изменении калькулятора требуется новая проверка и обновление снимка.

## Проверки

21 автоматический тест: прежнее меню и профили, ошибки и ограничения webhook, failover ИИ, точность больших чисел, поля источника, выбор серверов и альянсов, подтверждение импорта, отсутствие ID в ответах, HTML-экранирование и фильтр дефицита. Дополнительно выполнены живые запросы к группам, серверам, альянсу и игроку, сверка текущей мощи в карточке и составе, формирование живого отчёта. Эти проверки не заменяют просмотр сообщения в настоящем Telegram.

## Загрузка в GitHub — выполняет владелец

В каталоге UPDATE-FILES находятся только новые и изменённые файлы. Не нужно очищать репозиторий и удалять файлы снова.

1. Откройте репозиторий на GitHub и создайте ветку `alliance-spirit-update` из `main`.
2. **Add file → Upload files**. Перетащите все файлы из UPDATE-FILES прямо в корень ветки, без самой папки.
3. Подтвердите замену прежних файлов, затем **Commit changes**.
4. Создайте pull request в `main`, проверьте состав изменений, выполните **Merge pull request → Confirm merge**.
5. GitHub Actions в плоской версии отсутствуют: автоматические тесты выполнялись локально. GitHub-загрузка сама по себе не размещает Worker.

Ни одного действия в GitHub за владельца не выполнено. Секреты и игровые профили в пакет не входят. Адрес Worker и webhook остаются прежними; повторно вводить токен не требуется.

## Проверка в Telegram

Отправьте `/start`, затем **Духи → Сервер и альянс → группа → сервер → альянс → Сравнить с уровнем → уровень события → волна**. В отчёте должны быть только ники с дефицитом, выделенные жирным, без ID. Числа тестовых записей не публикуются как игровые данные.

При отсутствии знакомого сервера используйте «Ввести номер». Если запись отсутствует или сайт временно недоступен, бот сообщит об этом, сохранив прежнюю мощь профиля. Для привязки игрока можно использовать «Мой профиль → Загрузить по ID».
